1. Random Forest

Think of it as many small decision trees voting on the same heart-rate pattern. It learns from examples labelled normal or unusual.

Features→Many trees→Majority vote

2. Isolation Forest

It learns what the normal feature space looks like. A pattern that is easy to separate from that normal region receives an anomaly signal.

Normal profile→Isolation→Anomaly signal

3. How the final answer is produced

Heart-rate values→6 features→Two AI signals→Threshold rules→Result + confidence + explanation
Important: The displayed model metrics come from synthetic educational data. They demonstrate the ML engineering pipeline; they are not clinical validation.

Why the project is built this way

Separation of concerns. Data collection, AI analysis, storage and presentation are separate layers. That makes the system easier to test, extend and connect to real hardware.

Hardware-independent today. The laptop simulator proves the software architecture before hardware is purchased.

What can be added next

  • ESP32 + MAX30102 sensor acquisition
  • Blynk or another cloud notification layer
  • Secure production deployment
  • Validated biomedical datasets
  • Formal privacy, security and regulatory controls
Responsible use: PulseGuard AI is an educational prototype. It does not diagnose conditions or provide treatment advice. The 60/100 BPM values are demonstration thresholds from the project brief.
